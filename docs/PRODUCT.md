# Описание продукта — черновик этапа 1

Структура соответствует приложению А методички. Документ требует уточнения пользователя и границ MVP после согласования заявки; тег `v0.1` ещё не создан.

## Название

RAG-чатбот по документам (рабочее название; финальное определяется на этапе MVP).

## Пользователь

Основной сегмент пока не выбран. Рабочая гипотеза — специалист небольшой организации, который ищет сведения в договорах, регламентах и отчётах на своём компьютере и не пользуется терминалом или API. Выбор и подтверждение сегмента относятся к заявке этапа 0.

## Проблема

Нужный фрагмент ищется вручную в нескольких документах; поиск по словам не объединяет сведения из разных файлов. Предполагаемая частота — несколько раз в неделю, её нужно подтвердить для выбранного пользователя. Сканированные PDF без текстового слоя в MVP не обрабатываются: OCR вынесен за его границы.

## Как пользователь решает проблему сейчас

- открывает каждый файл и ищет вручную;
- копирует фрагменты в ChatGPT/DeepSeek и теряет привязку к странице и файлу;
- просит коллег посмотреть.

## Почему новое решение лучше

- ответ со ссылкой на файл и страницу;
- в локальном режиме документы не покидают компьютер;
- установка и запуск как обычной программы, без терминала и настройки окружения;
- повторные вопросы не расходуют API — кэш снижает расходы пользователя.

## MVP — состав

- добавление папки или файлов PDF, DOCX, TXT через интерфейс;
- индексация с сохранением между запусками;
- вопрос → ответ с цитатами (файл и страница);
- история диалога;
- кэш повторных вопросов и индикатор «ответ из кэша, запрос не потрачен»;
- два варианта сборки: THIN (внешний API) и FAT (локальная модель);
- режим «Только локально» для конфиденциальных документов: внешние провайдеры заблокированы, сетевые запросы отсутствуют;
- запуск в один клик, понятные сообщения об ошибках (повреждённый PDF, файл с паролем, пустой файл, отсутствие текстового слоя).

## Не входит в MVP

| Что | Причина |
|---|---|
| OCR сканов | требует отдельного движка; документ без текстового слоя помечается соответствующим статусом |
| Синхронизация между устройствами и облако | вне предметной области; противоречит локальному режиму |
| Мобильные ОС | иная платформа и интерфейс |
| Многопользовательская работа и права доступа | вне предметной области |
| Шифрование индекса на диске | оценивается после MVP |
| Вендорский прокси к API и подписка | требует сервера и защиты ключей; вне рамок текущей версии |

## Аналоги

| Аналог | Отличие продукта |
|---|---|
| Облачный чат с загрузкой файлов | передача документов третьей стороне неприемлема для локально ограниченных файлов |
| Локальные RAG-приложения | заменяют ручной поиск; сравнение удобства установки и работы ещё требуется |
| Ручной поиск по файлам | не формирует единый ответ по нескольким документам |

## Монетизация

**Выбранный вариант: разовая покупка + ключ пользователя.**

| Вариант | Как работает | Оценка |
|---|---|---|
| **A. Разовая покупка + ключ пользователя** (выбрано) | пользователь покупает приложение и подключает свой API-ключ либо использует локальную модель | себестоимость у вендора нулевая; локальный режим не требует затрат; ответственность за чужие токены отсутствует |
| B. Подписка с вендорским API | ежемесячная плата покрывает расход на API | вендорские ключи нельзя размещать в десктопном клиенте; требуется сервер-прокси; расход на токены входит в себестоимость; локальная модель снижает ценность подписки |

Кэш ответов (требование №2) снижает расход пользователя на его собственный ключ и является частью ценности продукта.
Локальная сборка позиционируется как издание для документов, которые нельзя передавать третьим лицам, и как вариант без оплаты API.

## Конфиденциальность и границы доверия

| Данные | Локальная сборка / режим «Только локально» | Сборка с внешним API |
|---|---|---|
| Текст документов | остаётся на компьютере пользователя | передаётся провайдеру, только для документов с разрешением |
| Эмбеддинги | локальная модель | локальная модель (текст не передаётся ради индексации) |
| Индекс, кэш, история | локальное хранилище; формат выбирается на этапе 2 | локальное хранилище; формат выбирается на этапе 2 |
| API-ключ | не требуется | способ хранения определяется на этапе 2; открытый файл исключён |
| Логи | без текста документов и ответов | без текста документов; ключ маскирован |
| Телеметрия | выключена | выключена по умолчанию |

Проверяемость: автоматический тест «ноль сетевых вызовов» при локальном провайдере. Текст для интерфейса утверждается после реализации и проверки обеих сборок.

## Критерий готовности

Пользователь устанавливает приложение, добавляет папку с документами, задаёт 5 вопросов и получает ответы с цитатами; повторный вопрос отвечает мгновенно из кэша без сетевого запроса; документ в режиме «только локально» обрабатывается без единого сетевого запроса; после перезапуска индекс и история сохраняются; тесты запускаются одной командой; репозиторий собирается по README из чистых каталогов.
