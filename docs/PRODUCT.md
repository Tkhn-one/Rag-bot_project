# Описание продукта — черновик этапа 1

Структура соответствует приложению А методички. Пользователь, состав MVP и требования уточнены по договорённостям со студентом 17.09.2026. Документ подготовлен для этапа 1; его формальное предъявление, завершение этапа и тег `v0.1` ещё не зафиксированы. Продукт не реализован, свойства ниже — требования и гипотезы, а не результаты испытаний.

## Название

RAG-чатбот по документам (рабочее название; финальное определяется на этапе MVP).

## Пользователь

Основной сегмент — сотрудник небольшой организации, который ищет сведения о продукции в технических паспортах, спецификациях, инструкциях и сопроводительных материалах на своём компьютере. Работа с приложением не должна требовать терминала или настройки окружения.

Это фокус проверки MVP, а не ограничение универсальности: приложением могут пользоваться также бухгалтеры, студенты и другие люди, работающие с документами. Конфиденциальность определяется политикой обработки документов, а не профессией.

## Проблема

Нужная характеристика или условие находится среди множества файлов, и пользователь не знает, в каком именно. Приходится открывать документы по очереди, искать и сопоставлять сведения вручную; важны время поиска и возможность проверить ответ по первоисточнику. Конфиденциальные документы нельзя передавать внешнему провайдеру без разрешения. Частота задачи и типичный объём библиотеки пока не измерены. Сканированные PDF без текстового слоя в MVP не обрабатываются: OCR вынесен за его границы.

## Как пользователь решает проблему сейчас

- открывает каждый файл и ищет вручную;
- загружает документы или копирует фрагменты в ChatGPT, Gemini или DeepSeek и проверяет полученный ответ вручную.

Это описание студента, не результат пользовательского исследования. Лимиты загрузки и сравнительные возможности сервисов требуют отдельной проверки.

## Ожидаемая ценность и её проверка

- быстрый поиск по всей добавленной библиотеке, а не только по отдельной порции файлов;
- ответ по найденным подтверждениям, цитаты и гиперссылки к источнику; файл и страница/строка при наличии;
- при недостатке подтверждений — сообщение об этом вместо дополнения ответа догадками;
- в локальном режиме документы не покидают компьютер;
- установка и запуск как обычной программы, без терминала и настройки окружения;
- повторные вопросы не расходуют API — кэш снижает расходы пользователя.

Скорость, достоверность и удобство будут проверены на демонстрационных вопросах и тестах; абсолютное отсутствие ошибок и преимущество над аналогами пока не доказаны. При проверке нужно сопоставлять ответ с первоисточником, включая случаи отсутствия подтверждений.

## MVP — состав

- добавление папки или файлов PDF, DOCX, TXT через интерфейс;
- индексация с сохранением между запусками;
- поиск по всей добавленной библиотеке без искусственного лимита на число документов;
- вопрос → ответ по найденным подтверждениям с цитатами и гиперссылками; файл, страница и строка при наличии, иначе доступный ориентир;
- сообщение о недостатке подтверждений, если ответ не найден;
- история диалога;
- кэш повторных вопросов и индикатор «ответ из кэша, запрос не потрачен»;
- два варианта сборки: THIN (внешний API) и FAT (локальная модель), с выбором доступной нейросети пользователем;
- режим «Только локально» для конфиденциальных документов: внешние провайдеры заблокированы, сетевые запросы отсутствуют;
- запуск в один клик, понятные сообщения об ошибках (повреждённый PDF, файл с паролем, пустой файл, отсутствие текстового слоя).

Состав MVP подтверждён студентом. Практический объём ограничивается ресурсами компьютера. Рекомендуемый размер библиотеки, время индексации и ответа, расход API будут определены экспериментами; фиксированная скорость при любом количестве документов не обещается.

## Не входит в MVP

| Что | Причина |
|---|---|
| OCR сканов | требует отдельного движка; документ без текстового слоя помечается соответствующим статусом |
| Синхронизация между устройствами и облако | вне предметной области; противоречит локальному режиму |
| Мобильные ОС | иная платформа и интерфейс |
| Многопользовательская работа и права доступа | вне предметной области |
| Редактирование документов | приложение отвечает на вопросы, а не изменяет исходники |
| Автоматические резюме и пересказы | возможное расширение после MVP |
| Шифрование индекса на диске | оценивается после MVP |
| Вендорский прокси к API и подписка | требует сервера и защиты ключей; вне рамок текущей версии |

## Аналоги

| Аналог или заменитель | Направление сравнения |
|---|---|
| ChatGPT / Gemini / DeepSeek с загрузкой файлов | проверяемость ответа, время поиска, лимиты загрузки и обработка конфиденциального текста |
| Локальные RAG-приложения, например AnythingLLM / GPT4All | удобство установки, поиск и переход к источнику; сравнение ещё требуется |
| Ручной поиск по файлам | время поиска и сопоставления сведений из разных документов |

Конкретные лимиты и преимущества над сервисами пока не проверены; таблица задаёт план сравнения, а не устанавливает недостатки конкурентов.

## Монетизация

**Выбранный вариант: разовая покупка + ключ пользователя.**

| Вариант | Как работает | Оценка |
|---|---|---|
| **A. Разовая покупка + ключ пользователя** (выбрано) | пользователь покупает приложение и подключает свой API-ключ либо использует локальную модель | вендор не оплачивает API-токены пользователя; локальный режим не требует платежей за API; затраты на разработку и поддержку не считаются нулевыми |
| B. Подписка с вендорским API | ежемесячная плата покрывает расход на API | вендорские ключи нельзя размещать в десктопном клиенте; требуется сервер-прокси; расход на токены входит в себестоимость; локальная модель снижает ценность подписки |

Кэш ответов (требование №2) снижает расход пользователя на его собственный ключ и является частью ценности продукта.
Локальная сборка позиционируется как издание для документов, которые нельзя передавать третьим лицам, и как вариант без оплаты API.

Цена и валюта пока не указываются по решению студента: они зависят от конечного результата. После проверки функциональности и ценности потребуется обоснование цены и готовности пользователя платить; отсрочка не считается выполненным исследованием монетизации. Для завершения этапа 1 нужно указать предполагаемую цену с аргументом либо согласовать отсрочку с преподавателем; такого согласования в записях нет (раздел 11 и приложение А методички). ADR-007 принят 15.09.2026, подтверждение студента получено в обсуждении.

## Выбранный стек

C++20 + CMake + Qt 6 выбраны студентом 17.09.2026 (ADR-001 и ADR-003). Qt относится только к Presentation; CLI и GUI используют одни сценарии и правила, различаясь комфортом взаимодействия. Подробная архитектура, хранилище и локальная модель остаются задачами этапа 2.

## Конфиденциальность и границы доверия

| Данные | Локальная сборка / режим «Только локально» | Сборка с внешним API |
|---|---|---|
| Текст документов | остаётся на компьютере пользователя | передаётся провайдеру, только для документов с разрешением |
| Эмбеддинги | локальная модель | локальная модель (текст не передаётся ради индексации) |
| Индекс, кэш, история | локальное хранилище; формат выбирается на этапе 2 | локальное хранилище; формат выбирается на этапе 2 |
| API-ключ | не требуется | способ хранения определяется на этапе 2; открытый файл исключён |
| Логи | без текста документов и ответов | без текста документов и ответов; ключ маскирован |
| Телеметрия | выключена | выключена по умолчанию |

Политика обработки принята 15.09.2026 (ADR-008), по подтверждению студента. Проверяемость: автоматический тест «ноль сетевых вызовов» при локальном провайдере. Текст для интерфейса утверждается после реализации и проверки обеих сборок. Локальное хранение само по себе не является заявлением о защите от доступа других пользователей ПК; шифрование индекса не входит в MVP.

## Критерий готовности

Пользователь устанавливает приложение без терминала, добавляет папку с документами, задаёт 5 вопросов и проверяет ответы по цитатам и гиперссылкам; вопрос без достаточных подтверждений получает соответствующее сообщение. Повторный вопрос при неизменных индексе и модели обслуживается из кэша без нового вызова провайдера. Документ в режиме «только локально» обрабатывается без сетевых запросов; после перезапуска индекс и история сохраняются. Ожидаемые ошибки не приводят к аварийному завершению; тесты запускаются одной командой; репозиторий собирается по README из чистого каталога сборки. Проверяются обе сборки.

500 документов / 2 000 страниц, 5 с для внешней модели без задержки сети, 30 с для локальной на ПК 8 ядер / 16 ГБ RAM и менее 1 с для кэша — исходные непроверенные ориентиры из заявки, не ограничения и не гарантии. Модель, оборудование и методика измерения уточняются перед испытаниями; рекомендации пользователю публикуются по результатам.
