## 4. Проблема

<Как проявляется: нужный пункт договора или абзац регламента ищется вручную; поиск по PDF не работает по сканам и плохо работает по DOCX; файлов десятки, объём — сотни страниц. Как часто: несколько раз в неделю.>
<К потерям: время на поиск; риск пропустить условие; невозможность использовать облачные сервисы, так как документы нельзя передавать третьим лицам.>

## 5. Текущий способ решения и его недостатки

<Варианты: ручной поиск в каждом файле; Ctrl+F; копирование фрагментов в чат-боты. Не устраивает: медленно; нет привязки ответа к странице; облачные сервисы неприемлемы по условиям конфиденциальности.>

## 6. Преимущество продукта

Сочетание: точность цитирования (ответ с указанием файла и страницы), приватность (локальный режим без сетевых запросов), экономия (повторные вопросы не расходуют API), работа без терминала и настройки окружения.

Наблюдаемая проверка:
- ответ содержит имя файла и номер страницы;
- в локальном режиме число сетевых вызовов равно нулю (автоматический тест);
- повторный вопрос возвращает ответ из кэша за время меньше секунды;
- установка и запуск выполняются без командной строки.

## 7. Состав MVP

<Подтвердить полностью или исключить пункты.>

- добавление папки или отдельных файлов PDF, DOCX, TXT;
- индексация с сохранением между запусками;
- вопрос → ответ с цитатами (файл и страница);
- история диалога;
- кэш повторных вопросов с индикатором «ответ из кэша»;
- два варианта сборки: THIN (внешний API) и FAT (локальная модель);
- режим «Только локально» для конфиденциальных документов;
- понятные сообщения об ошибках (повреждённый PDF, файл с паролем, пустой файл, отсутствие текста);
- графический интерфейс.

## 8. Не входит в MVP

| Что | Причина |
|---|---|
| OCR сканов | отдельный движок; документ без текстового слоя получает соответствующий статус |
| Совместная работа и права доступа | вне предметной области |
| Мобильные ОС | иная платформа |
| Облачная синхронизация | противоречит локальному режиму |
| Редактирование документов | продукт отвечает на вопросы, а не изменяет файлы |
| Автоматические резюме и пересказы | расширение после MVP |
| Шифрование индекса на диске | оценивается после MVP |

## 9. Аналоги и заменители

| Аналог | Недостаток, который устраняет проект |

## 11. Технические решения

| Поле | Значение |
|---|---|
| Язык | C++20 и CMake (по умолчанию методички); Python — только по согласованию <подтвердить> |
| GUI | настольное приложение (платформа определяется на этапе 2) |
| Модули | domain, application, infrastructure, presentation, tests |

| Кэш | декоратор над провайдером; ключ = вопрос + версия индекса + идентификатор модели |

| Ключ API | системное хранилище секретов |
| Сборки | `WITH_LOCAL_LLM=ON/OFF` — локальное издание и издание с внешним API |

## 12. План первой вертикальной версии

Загрузка одного TXT → разбиение на фрагменты → ответ через MockProvider (без сети) → вывод ответа с цитатой в консольном интерфейсе → автоматический тест сценария.
