## 3. Пользователь

Основной сегмент MVP — сотрудник небольшой организации, который работает с большим количеством документов о продукции: техническими паспортами, спецификациями, инструкциями и сопроводительными материалами. Пользователь ищет сведения на своём компьютере и не должен настраивать окружение или пользоваться терминалом.

Фокус MVP нужен для проверки ценности и не ограничивает универсальность приложения: им могут пользоваться также бухгалтеры, студенты и другие люди, работающие с документами. Конфиденциальность определяется политикой обработки библиотеки/документа, а не профессией пользователя.

## 4. Проблема

Нужная характеристика или условие находится в одном из множества документов, но пользователь не знает, в каком именно. Приходится открывать файлы по очереди и искать вручную, иногда сопоставляя несколько источников. Это занимает время и создаёт риск пропустить важное условие или получить неподтверждённый ответ. Для конфиденциальных документов передача текста внешним сервисам может быть запрещена.

Частота задачи и типичный объём библиотеки пока не измерены; интервью и проверка на реальных обезличенных примерах не проводились в рамках этой работы.

## 5. Текущий способ решения и его недостатки

Пользователь открывает файлы и ищет вручную либо обращается к большим языковым моделям, например ChatGPT, Gemini или DeepSeek. По описанию студента важны время поиска, проверяемость ответа, возможность работать с множеством документов и запрет передачи конфиденциального текста. Конкретные ограничения и сравнительные характеристики сервисов пока не проверены; превосходство проекта над ними не заявляется как установленный факт.

Основной сценарий: добавить документы о продукции → задать вопрос → получить ответ по найденным подтверждениям → перейти по гиперссылке к источнику и проверить цитату. Если подтверждений недостаточно, приложение сообщает об этом, а не дополняет ответ догадками. Пример вопроса для будущего демо: «Какой диапазон рабочих температур указан для изделия?»; тестовые документы ещё предстоит подобрать.

## 6. Преимущество продукта

Цель: быстрый поиск по всей добавленной библиотеке, ответ с подтверждающими цитатами и переходом к источнику, приватность локального режима, экономия повторных API-запросов, работа без терминала. Это требования и гипотезы ценности, а не уже доказанные преимущества или гарантия абсолютной безошибочности.

Наблюдаемая проверка:

- ответ содержит подтверждающие цитаты, гиперссылку и имя файла; страницу и строку — если доступны, иначе доступный ориентир;
- при недостатке подтверждений выводится понятное сообщение, а не выдуманные сведения;
- в локальном режиме число сетевых вызовов равно нулю (автоматический тест);
- повторный вопрос при неизменном индексе и модели возвращает ответ из кэша без нового вызова провайдера; целевое время требует измерения;
- установка и запуск выполняются без командной строки.

## 7. Состав MVP

Состав подтверждён студентом.

- добавление папки или отдельных файлов PDF, DOCX, TXT;
- индексация с сохранением между запусками;
- поиск по всей добавленной библиотеке без искусственного лимита на число документов;
- вопрос → ответ по найденным подтверждениям с цитатами и гиперссылками (файл, страница и строка при наличии); сообщение о недостатке подтверждений;
- история диалога;
- кэш повторных вопросов с индикатором «ответ из кэша»;
- два варианта сборки: THIN (внешний API) и FAT (локальная модель), с выбором доступной нейросети пользователем;
- режим «Только локально» для конфиденциальных документов;
- понятные сообщения об ошибках (повреждённый PDF, файл с паролем, пустой файл, отсутствие текста);
- графический интерфейс.

Практический объём ограничен ресурсами компьютера. Рекомендации по размеру библиотеки и оценка расхода API будут подготовлены по измерениям; отсутствие искусственного лимита не означает бесконечную ёмкость или постоянное время ответа.

## 8. Не входит в MVP

| Что | Причина |
|---|---|
| OCR сканов | отдельный движок; документ без текстового слоя получает соответствующий статус |
| Совместная работа и права доступа | вне предметной области |
| Мобильные ОС | иная платформа |
| Облачная синхронизация | противоречит локальному режиму |
| Редактирование документов | продукт отвечает на вопросы, а не изменяет файлы |
| Автоматические резюме и пересказы | расширение после MVP |
| Шифрование индекса на диске | оценивается после MVP |

## 9. Аналоги и заменители

| Аналог или заменитель | Что предстоит сравнить |
|---|---|
| ChatGPT / Gemini / DeepSeek с загрузкой файлов | подтверждение ответа источниками, время поиска, лимиты загрузки и пригодность для конфиденциальных документов |
| AnythingLLM / GPT4All | удобство установки, локальной обработки и перехода к источникам; сравнение не проведено |
| Ручной поиск (Ctrl+F, просмотр файлов) | время поиска и сопоставления сведений по нескольким документам |

Это список для будущего сравнения. Конкретные лимиты конкурентов, включая упомянутый студентом лимит DeepSeek, не включаются как проверенные факты без проверки.

## 10. Монетизация

| Поле | Значение |
|---|---|
| Модель | разовая покупка; ключ API приобретает и оплачивает пользователь; локальный режим работает без ключа |
| Цена | пока не указывается; зависит от конечного результата |
| Обоснование отсрочки | цену и готовность пользователя платить оценить после проверки ценности; отсрочка записана, но её принятие преподавателем не подтверждено. Для завершения этапа 1 нужна ценовая гипотеза с аргументом либо согласованная отсрочка (раздел 11 и приложение А) |
| Отклонённая альтернатива | подписка с API вендора: ключи нельзя размещать в десктопном клиенте, требуется сервер-прокси; вне рамок текущей версии |

### Предварительные сущности и классы

Набор понятий подтверждён студентом. Это основа объектной модели всей программы, а не перечисление шагов алгоритма; необходимость отдельных классов и их интерфейсы проверяются на этапе 2.

| Объект | Ответственность |
|---|---|
| Документ | текст, сведения об исходном файле, формат и статус обработки |
| Библиотека документов | набор файлов для поиска и политика разрешённой обработки |
| Фрагмент документа | участок текста с сохранённым местоположением в источнике |
| Вопрос | запрос пользователя к библиотеке |
| Ответ | результат по найденным подтверждениям либо сообщение о недостатке сведений |
| Цитата-ссылка | подтверждающая выдержка, файл и доступный ориентир для перехода к источнику |

Основные службы для проектирования: импорт, индексация и поиск, провайдер модели, кэш и сохранение. Подробные классы GUI и инфраструктуры сейчас не утверждаются; искусственные классы ради количества не добавляются.

### Основные технические риски (разделы 16–17 методички)

Это предварительная оценка рисков для заявки, а не принятые архитектурные решения или результаты испытаний.

| Риск | Как предлагается проверить и снизить |
|---|---|
| Слишком большой объём: GUI, три формата и две сборки | Согласовать границы MVP и начать с одного сквозного TXT-сценария без сети; затем добавлять функции по этапам |
| Локальная модель не помещается в память или отвечает слишком медленно | На этапе 2 выбрать целевой ПК и модель, проверить память и задержку до обещаний о производительности |
| Ответ или цитата не подтверждаются документом | Подготовить вопросы с известными ответами и вопрос без ответа; сверять цитаты с источником |
| Конфиденциальный текст отправляется наружу | Единая проверка политики, отказ при `LocalOnly` с удалённым провайдером и тест отсутствия сетевых вызовов |
| Кэш выдаёт устаревший ответ | Проверить повторный вопрос и изменение документов/модели; хранение и реализацию выбрать на этапе 2 |
| PDF/DOCX не извлекаются корректно, ломается привязка к источнику | Проверить разные файлы и ошибки; OCR исключён из MVP, номера страниц и строк не выдумываются |
| Зависимости и веса модели затрудняют сборку или распространение | До включения согласовать библиотеки, проверить совместимость с C++/Qt и условия распространения |

## 12. План первой вертикальной версии

Предложение: загрузка одного TXT → разбиение на фрагменты → поиск → ответ через MockProvider (без сети) → вывод ответа с цитатой в консольном интерфейсе → автоматический тест сценария, включая пограничный случай.

Прототип ещё не согласован с преподавателем; в записи от 17.09.2026 студент планировал уточнить его примерно через две недели. Новых результатов согласования на 28.09.2026 не подтверждено. По подтверждению студента консольный интерфейс на промежуточном этапе разрешён. GUI добавляет комфорт использования, но не меняет правила поиска, ответа и проверки приватности.

## 13. Критерий готовности с измеримыми условиями

Условия ниже — будущие критерии проверки, не результаты работающего продукта. Студент подтвердил, что численные значения являются ожиданиями без измерений.

| Условие | Значение |
|---|---|
| Целевые ОС | Windows 10/11 — плановый приоритет; macOS — при наличии времени; совместимость ещё не проверена |
| Размер библиотеки | без искусственного лимита на число документов; практическая ёмкость и рекомендации зависят от ресурсов ПК и измерений |
| Ориентир нагрузочного теста | 500 документов / 2 000 страниц — непроверенная гипотеза, не предел продукта |
| Время ответа, внешний API | 5 с без задержки сети — непроверенная цель; методику измерения ещё нужно определить |
| Время ответа, локальная модель | 30 с на ПК 8 ядер / 16 ГБ RAM — непроверенная цель, модель ещё не выбрана |
| Повторный вопрос | ответ из кэша без нового вызова провайдера при неизменном индексе и модели; менее 1 с — непроверенная цель |
| Источник | гиперссылка к найденному месту, где поддерживается; имя файла, страница/строка при наличии, иначе доступный ориентир |
| Недостаточно подтверждений | сообщение о недостатке сведений; отсутствие подтверждённого ответа не заменяется догадкой |
| Отсутствие сети | понятное сообщение; предложение локального режима только если он доступен, без аварийного завершения |
| Конфиденциальный документ | ноль сетевых запросов (автоматический тест) |
| Запуск | без командной строки; сборка и тесты одной командой из README |

Демонстрация MVP: установка → добавление папки → пять вопросов и проверка цитат → повторный вопрос из кэша → проверка локальной обработки без сети → перезапуск с сохранённым индексом и историей. Отдельно показывается вопрос без достаточных подтверждений. Абсолютная безошибочность и превосходство по скорости без испытаний не заявляются.
