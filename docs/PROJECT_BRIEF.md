# Постановка проекта

Краткое изложение темы и обязательных условий преподавателя. Пользователь, MVP и критерий готовности описаны в `PRODUCT.md`; этапы — в `ROADMAP.md`; технические варианты — в `ARCHITECTURE.md` и `DECISIONS.md`.

Студент 06.10.2026 подтвердил: заявка и объём проекта приняты преподавателем **15.09.2026**, уровень — **продвинутый**. Замечание касалось выбора языка: первоначально рассматривался Python. Конкретные контрольные даты не назначены. Подробности — в `APPLICATION.md`.

## Тема

**RAG-чатбот по документам как десктопное приложение для обычного пользователя** (не для разработчика): пользователь добавляет свои PDF/DOCX/TXT и получает ответы по всей добавленной библиотеке с подтверждающими цитатами и гиперссылками на источник. Страница и строка указываются, если доступны; иначе используется доступный ориентир, без выдумывания номеров.
**Одна кодовая база — два варианта поставки:** тонкий клиент с внешним API (ключ пользователя) и локальное издание со встроенной llama, работающее полностью офлайн. Повторные вопросы не расходуют API — ответы кэшируются.

## Требования преподавателя

| № | Требование | Выбранный или предложенный способ выполнения (код отсутствует) |
|---|---|---|
| 1 | Платформа для обычного пользователя, не «питон-бэкендер» | Настольный GUI (слой Presentation) поверх Domain/Application; GUI — расширение, а не замена архитектуры (п. 5 методички) |
| 2 | Повторный вопрос не должен делать новый запрос к API (себестоимость при монетизации) | Кэш ответов: ключ = нормализованный вопрос + версия индекса + id модели; инвалидация при изменении документов; счётчик сэкономленных запросов |
| 3 | Два варианта приложения | Одна кодовая база, две сборки: THIN (внешний API) и FAT (встроенная llama) |
| 4 | Выбор нейросети | Провайдер как заменяемая деталь: интерфейс `ILlmProvider`, реализации `RemoteApiProvider` и `LocalLlamaProvider`, `MockProvider` для тестов |
| 5 | Монетизация | Разовая покупка + ключ пользователя (вариант A). Подписка с вендорским API вне рамок текущей версии: требует сервера-прокси для защиты ключей (ADR-007) |
| 6 | Документы, которые нельзя передавать третьим лицам | Режим «Только локально» на уровне библиотеки: внешние провайдеры заблокированы, проверяется тестом «ноль сетевых вызовов» (ADR-008) |

Специальные требования записаны со слов студента и дополняют методичку. Конкретные способы выполнения в третьем столбце — решения и предложения проекта, а не подтверждение их отдельного утверждения преподавателем; статусы — в `DECISIONS.md`. В частности, требование монетизации и выбор модели «разовая покупка + ключ пользователя» различаются.

## Подтверждённые границы

- Основной сегмент MVP: руководитель проектов организации N, сопоставляющий ТЗ с договором и документами о принятых, выполненных и отложенных решениях. Организация N — условное обозначение; универсальность приложения сохраняется.
- Рабочие гипотезы: до 30 документов, около 20 вопросов в день, ответ не более чем за 5 минут после индексации. Это ориентиры испытаний, а не измеренные показатели; объём текста, оборудование и модель уточняются до проверки.
- Продуктовая цель: быстрый поиск по множеству документов, ответы только по найденным подтверждениям и сообщение о недостатке сведений. Скорость и достоверность ещё не проверены; абсолютная безошибочность не заявляется.
- Искусственный лимит на число документов в библиотеке не планируется; практический объём ограничивается ресурсами ПК. Рекомендации по объёму будут основаны на измерениях.
- OCR не входит в MVP; скан без текстового слоя получает понятный статус. Добавление OCR возможно после MVP.
- Предполагаемая цена — 15 000 ₽ за лицензию, разовая покупка; внешний API оплачивает пользователь своим ключом. Готовность платить и экономия времени не измерены.
