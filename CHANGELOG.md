# Журнал изменений

Здесь фиксируются фактические изменения предъявляемых версий по разделу 9 методички. План версий находится в `docs/ROADMAP.md`. Запланированные функции не записываются как выполненные.

## В работе — третья часть этапа 4

- Добавлена цепочка `CachingLlmProvider(ValidatingLlmProvider(MockProvider))`. Проверка допуска предшествует поиску и чтению кэша. В кэш попадают ответы с проверенной цитатой TXT, PDF или DOCX. Ключ SHA-256 учитывает нормализованный вопрос, ID и ревизию библиотеки и профиль модели.
- Схема SQLite 5 сохраняет кэш и историю самостоятельных вопросов. CLI отмечает ответ из кэша, показывает историю командой `--history` и очищает её командой `--clear-history`. При просмотре видны источники, время UTC, модель, ревизия и её устаревание.

- В схеме SQLite 4 библиотека получила постоянный ID и ревизию индекса. Добавление документа и смена политики публикуются вместе с новой ревизией. Дубликат, повторное разрешение, ошибка и перезапуск сохраняют прежнюю ревизию.
- При открытии схем 1–3 создаётся резервная копия. Миграция сохраняет документы, их политики, ID и позиции цитат TXT, PDF и DOCX.
- Для вопроса хранилище возвращает согласованный снимок всей библиотеки. Провайдер объявляет тип обработки и ID модели. Внешний профиль требует разрешения библиотеки и каждого документа до поиска. Тесты со счётчиками проверяют отказ и успешный локальный запрос по тому же набору.

## В работе — вторая часть этапа 4

- Добавлен локальный импорт DOCX через miniz 3.1.2 и pugixml 1.16. Цитаты из основного текста, таблиц, колонтитулов и сносок содержат имя части и номер абзаца либо координаты ячейки.
- Распаковка и чтение XML ограничены по объёму и структуре. При ошибке ZIP или нужной XML-части документ целиком пропускается. Удалённые правками фрагменты и внешние связи исключены из поиска.
- SQLite версии 3 сохраняет позиции DOCX. Миграция схемы 2 создаёт резервную копию и сохраняет ID, строки TXT и страницы PDF. Добавлены учебный DOCX и сквозная проверка трёх форматов после перезапуска.
- Добавлен локальный импорт PDF с текстовым слоем через PDFium 160.0.8165.0. CLI выводит номер страницы, а SQLite сохраняет его для следующего запуска.
- При частичном импорте PDF CLI перечисляет страницы без текста. Для зашифрованного, повреждённого и полностью нетекстового PDF предусмотрены отдельные ошибки.
- Схема SQLite версии 2 сохраняет страницы. При открытии базы версии 1 создаётся резервная копия через SQLite Backup API и выполняется транзакционная миграция с сохранением ID, политики и строк TXT.
- Добавлены учебный PDF и проверки цитаты со страницы 2, перезапуска, ошибок PDF, совместимости и отката миграции.

## В работе — первая часть этапа 4

- CLI принимает несколько TXT и ищет по общей библиотеке в памяти. Команда с одним файлом по-прежнему поддерживается.
- Каждый новый документ получает ID и политику `LocalOnly`. Приложение проверяет ID, номер строки и текст цитаты и подставляет имя файла из библиотеки.
- Повторный импорт совпадающего декодированного текста сохраняет исходную запись. Ошибка одного файла изолирована от остальных импортов.
- В README добавлен пример запуска с двумя TXT. CTest проверяет цитирование второго файла, отклонение неверного источника, повторный и неудачный импорт и запуск CLI.
- Тесты с ID импортированного документа отдельно проверяют отклонение неверного номера строки и выдуманного текста цитаты.
- Хранилище назначает ID, обрабатывает повторный импорт и возвращает ошибки чтения и записи через общий контракт.
- Режим CLI с `--db` сохраняет TXT-библиотеку в SQLite 3.54.1. После повторного запуска цитата сохраняет имя источника, номер строки, текст и ID документа.
- SQLite сохраняет документ и фрагменты одной транзакцией, использует внешние ключи и проверяет версию схемы. CTest проверяет повторное открытие, импорт дубля, откат при сбое записи и отказ от открытия неподдерживаемой или повреждённой базы.
