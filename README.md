# RAG-чатбот по документам

Учебный проект по дисциплине «ООП. Современные паттерны» (Москва, 2026). Планируется настольное приложение для поиска ответов по библиотеке PDF, DOCX и TXT с подтверждающими цитатами и гиперссылками на источник. Основной пользователь MVP — сотрудник небольшой организации, работающий с техническими документами о продукции; универсальность приложения сохраняется. Одна кодовая база должна поддерживать внешнюю модель с ключом пользователя и локальную модель для документов, которые нельзя передавать третьим лицам. Повторный вопрос при неизменных индексе и модели должен обслуживаться из кэша.

[Предыдущий прототип](https://github.com/Tkhn-one/Rag-chatbot_docs) используется как источник идей; история этого проекта ведётся отдельно.

**Состояние проекта:** этап 0 — заявка заполнена по обсуждению со студентом, её предъявление и переход к этапу 1 ещё не зафиксированы. Тема согласована с преподавателем **15.09.2026**, уровень — **продвинутый**. Сейчас в репозитории только документы: исходников, `CMakeLists.txt` и тестов нет; сборка и запуск недоступны.

**Выбранный стек:** C++20 + CMake + Qt 6, по решению студента от 17.09.2026. Qt — слой интерфейса, а не бизнес-логика. Подробная архитектура, индекс и локальная модель ещё требуют решений.

Состав MVP подтверждён студентом; OCR не входит в MVP. Искусственный лимит на число документов не планируется, но практический объём ограничен ресурсами ПК. Скорость, достоверность и рекомендации по объёму ещё не проверены. При недостатке подтверждений приложение должно сообщать об этом, а не дополнять ответ догадками. Цена разовой покупки отложена до оценки результата; внешний API оплачивает пользователь своим ключом.

Проверено **28.09.2026** по репозиторию и исходному PDF методички. Студент попросил ориентироваться на имеющиеся записи: новых подтверждений согласования нет. Ближайший записанный ориентир показа — **13.10.2026**, минимум этапы 0 и 1; это план студента, а не назначенная преподавателем дата. Вертикальный прототип остаётся предложенным, но ещё не согласованным с преподавателем.

## Что утверждено

| Основание | Зафиксированный результат |
|---|---|
| Преподаватель, по записи со слов студента | Тема и продвинутый уровень — 15.09.2026; шесть специальных требований в [постановке](docs/PROJECT_BRIEF.md); CLI разрешён для промежуточного этапа |
| Решения студента | C++20 + CMake + Qt 6 — 17.09.2026; основной пользователь и MVP; разовая покупка с ключом пользователя и политика локальной обработки — ADR-007/008 от 15.09.2026 |
| Пока не подтверждено | Предъявление уточнённой заявки, завершение этапа 1, календарь четырёх показов, объём первого прототипа |
| Пока не выбрано / не проверено | Подробная архитектура, хранилище, модель и её лицензия, хранение ключа; цена, скорость и практический объём библиотеки |

Согласование темы не означает утверждения всех технических предложений. Для перехода к этапу 1 нужно предъявить уточнённую заявку и записать результат; список действий — в [плане](docs/ROADMAP.md).

В схеме раздела 10 журнал `AI_LOG.md` расположен в корне. Здесь он хранится в `docs/AI_LOG.md` вместе с проектными записями и доступен из таблицы документов; раздел 10 прямо допускает другую логически объяснённую структуру. `PROJECT_BRIEF.md`, `APPLICATION.md` и `ROADMAP.md` дополняют обязательные документы постановкой, заявкой и планом. `AGENTS.md` содержит локальные правила работы и не является отдельным требованием преподавателя.

`CMakeLists.txt`, `include/`, `src/`, `tests/` и `data/` будут добавлены вместе с соответствующим кодом и демонстрационными данными; пустые каталоги и фиктивная сборка не обозначают завершение этапа. Методичка не задаёт шрифт, поля, объём страниц или ГОСТ для этих Markdown-документов: она задаёт содержание, структуру и способ фиксации результатов.
