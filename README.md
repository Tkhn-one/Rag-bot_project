# RAG-чатбот по документам

Учебный проект по дисциплине «ООП. Современные паттерны» (Москва, 2026). Планируется настольное приложение для вопросов по библиотеке PDF, DOCX и TXT с подтверждающими цитатами и ссылками на источники.

Основной пользователь MVP — руководитель проектов организации N. Он сопоставляет ТЗ с договором и ищет сведения о принятых, выполненных и отложенных решениях. Организация N — условное обозначение; приложение может использоваться и для других документов.

**Текущий этап — 5, подготовка MVP.** Рабочее ядро этапа 4 зафиксировано версией `v0.5` от 26.11.2026. Вертикальный прототип — `v0.3`, архитектура — `v0.2`, продукт — `v0.1`. Заявка и объём приняты преподавателем 15.09.2026, уровень — продвинутый.

**Стек рабочего ядра** — C++20, CMake, SQLite с FTS5 и локальные парсеры под Windows x64. CLI использует тестовый провайдер по умолчанию. Ключ `--openai` выбирает OpenAI Responses API через WinHTTP, а `--local-model` в сборке FAT выбирает Qwen3-4B в процессе приложения. Один CPU-runtime llama.cpp обслуживает генератор и отдельную модель гибридного поиска.

Одна кодовая база должна поддерживать сборку с внешним API и ключом пользователя и сборку с локальной моделью. Конфиденциальные документы обрабатываются локально, повторные вопросы при неизменных индексе и модели — из кэша. OCR не входит в MVP.

THIN и FAT обе выполняют поиск локально и включают модель эмбеддингов; FAT дополнительно содержит локальный генератор. История сохраняется для просмотра, каждый вопрос самостоятельный — это уточнение студента от 26.10.2026.

**Гипотезы:** до 30 документов в рабочем наборе, около 20 вопросов в день, ответ не более чем за 5 минут после индексации. Число файлов не является искусственным пределом; время зависит от объёма текста, оборудования и модели. Предполагаемая цена — **15 000 ₽ за лицензию**, разовая покупка; внешний API оплачивается отдельно. Скорость и ответы локальной модели проверены на двух учебных TXT. Испытания рабочей нагрузки, сравнение с аналогами, экономия времени и готовность платить остаются задачами этапа MVP.

[Предыдущий прототип](https://github.com/Tkhn-one/Rag-chatbot_docs) используется как источник идей; история этого проекта ведётся отдельно.

## Сборка и демонстрация

Нужны MSVC из Visual Studio Build Tools 2022, Windows SDK и CMake 3.21 или новее. Откройте Developer PowerShell или Developer Command Prompt для Visual Studio 2022. Перед сборкой перейдите в папку проекта, где находится `CMakeLists.txt`. Команда `cmake -S .` использует текущую папку как источник. В Developer Command Prompt для перехода можно использовать `cd /d "C:\Projects\Rag-bot"`, подставив свой путь.

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DBUILD_GUI=OFF -DWITH_LOCAL_LLM=OFF
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
.\build\Debug\rag_cli.exe .\data\demo\contract.txt "Какой срок приёмки?"
```

При первой конфигурации CMake через `FetchContent` получает архив SQLite 3.54.1 и проверяет его SHA3-256 перед распаковкой. MSVC компилирует `sqlite3.c` в статическую библиотеку. Для конфигурации без сети скачайте архив заранее и добавьте к команде CMake `-DRAG_SQLITE_ARCHIVE=C:/Downloads/sqlite-amalgamation-3540100.zip`, подставив свой путь. CMake проверит ту же контрольную сумму. [Официальный архив SQLite 3.54.1](https://www.sqlite.org/2026/sqlite-amalgamation-3540100.zip)

CMake также проверяет SHA-256 архива PDFium 160.0.8165.0 для MSVC x64. Сборка PDFium отключает V8 и XFA. `pdfium.dll` копируется рядом с `rag_cli.exe`. Для конфигурации из скачанного архива добавьте `-DRAG_PDFIUM_ARCHIVE=C:/Downloads/pdfium-win-x64.tgz`. Сведения о лицензиях находятся в `LICENSE` и `licenses/` внутри архива. [Релиз PDFium и контрольная сумма](https://github.com/bblanchon/pdfium-binaries/releases/expanded_assets/chromium%2F8165)

Для DOCX CMake проверяет SHA-256 архивов miniz 3.1.2 и pugixml 1.16. MSVC собирает их статически. Для конфигурации из локальных архивов добавьте `-DRAG_MINIZ_ARCHIVE=C:/Downloads/miniz-3.1.2.zip` и `-DRAG_PUGIXML_ARCHIVE=C:/Downloads/pugixml-1.16.tar.gz`. [Релиз miniz](https://github.com/richgel999/miniz/releases/tag/3.1.2) · [Релиз pugixml](https://github.com/zeux/pugixml/releases/tag/v1.16)

Готовую программу можно запустить из любой папки. В Developer Command Prompt подставьте свои полные пути и введите всю команду одной строкой. Первый путь запускает `rag_cli.exe`, второй передаёт ему TXT-файл, третий аргумент задаёт вопрос. Если ввести путь к TXT отдельно, Windows откроет его в текстовом редакторе. В PowerShell перед первым путём добавьте `&`.

```cmd
"C:\Projects\Rag-bot\build\Debug\rag_cli.exe" "C:\Projects\Rag-bot\data\demo\contract.txt" "Какой срок приёмки?"
```

На учебном договоре программа показывает цитату «Срок приёмки результата составляет десять рабочих дней.» из строки 4. Вопрос «Астрономия» показывает сообщение об отсутствии подтверждения. Для пустого файла или вопроса программа выводит объяснение и возвращает ненулевой код завершения.

Для поиска по нескольким TXT перечислите пути к файлам перед вопросом. Вопрос передаётся последним аргументом в кавычках.

```powershell
.\build\Debug\rag_cli.exe .\data\demo\contract.txt .\data\demo\decisions.txt "Когда выполняется резервное копирование?"
```

В обоих файлах есть строка 4. В этом примере цитируется строка 4 из `decisions.txt` с ID документа 2. Программа присваивает ID при импорте в текущую библиотеку и берёт имя файла из сохранённых сведений об импорте. Она проверяет ID, строку и текст цитаты, которые вернул `MockProvider`.

Каждый TXT может занимать до 8 МиБ. Поддерживается UTF-8 с BOM и без него, а также UTF-16 с BOM. В приведённых командах библиотека существует в памяти до завершения программы. Новые документы получают политику `LocalOnly`. Если декодированный текст уже есть в библиотеке, сохраняются ID, имя и политика первого импортированного документа. Ошибка одного файла не отменяет остальные импорты. Если хотя бы один импорт завершился ошибкой, код завершения равен 1.

### Сохранённые исходники и цитаты (этап 5, шаг 1а)

При импорте через `--db` приложение копирует байты локального TXT, PDF или DOCX и индексирует эту копию. Рядом с БД создаётся каталог `sources/<ID библиотеки>/`. Имя копии образовано из SHA-256 и расширения формата. Повтор тех же байтов сохраняет ID, политику и исходное отображаемое имя. Разные файлы с одинаковым извлечённым текстом могут иметь разные ID. При переносе постоянной библиотеки перенесите и каталог с её копиями.

Пример для новой библиотеки в Release:

```powershell
$cli = '.\build\Release\rag_cli.exe'
$db = Join-Path .\build ('sources-demo-' + [guid]::NewGuid().ToString('N') + '.sqlite')
& $cli --db $db .\data\demo\contract.txt "Какой срок приёмки?"
& $cli --source $db 1 1
```

Два числа выбирают запись истории и цитату внутри ответа. Нумерация начинается с 1, записи видны через `--history`. Команда выводит сохранённый блок текста, координаты цитаты и проверенный путь к копии. Путь можно открыть в обычной программе для этого формата. Если копия пропала или её SHA-256 изменился, текст остаётся доступен, а команда показывает статус файла.

При открытии БД схемы 9 приложение сохраняет резервную копию штатным SQLite Backup API и переводит БД на схему 10 с прежними ID, ревизией, индексом, кэшем и историей. Старые цитаты указывают на сохранённый текст. Для этих документов приложение показывает «Исходная копия для этой записи не сохранялась». Новый импорт создаёт самостоятельную версию с проверяемыми байтами.

### Библиотека между запусками

Укажите `--db` и путь к базе SQLite. Первый запуск создаёт библиотеку и сохраняет оба TXT. Второй читает библиотеку из того же файла базы. Оба запуска показывают цитату из `decisions.txt`, строка 4, ID документа 2 для новой библиотеки.

```powershell
.\build\Debug\rag_cli.exe --db .\build\demo.sqlite .\data\demo\contract.txt .\data\demo\decisions.txt "Когда выполняется резервное копирование?"
.\build\Debug\rag_cli.exe --db .\build\demo.sqlite "Когда выполняется резервное копирование?"
```

SQLite хранит декодированный текст, имя источника, ID, политику и фрагменты с номерами строк. Для повторного вопроса достаточно файла базы. Каждый документ записывается вместе со всеми фрагментами в одной транзакции. Для недоступного или повреждённого файла и неподдерживаемой схемы CLI выводит ошибку.

### Кэш и история вопросов

При повторном запуске второй команды над той же библиотекой CLI выводит «Ответ из кэша.» и сохранённые утверждения с цитатами. Сначала приложение проверяет допуск профиля и выполняет поиск. При промахе оно вызывает провайдер, сверяет ID и дословный текст каждой цитаты с отправленными фрагментами и берёт имя источника и координаты из индекса. Смена ревизии библиотеки, модели, параметров или версии формата даёт другой ключ. Внешние пробельные символы вопроса удаляются, переводы строк приводятся к LF. Регистр, пунктуация и внутренние пробелы сохраняются.

Корректный ответ модели `InsufficientEvidence` сохраняется в кэше и истории. При отсутствии результатов поиска сообщение о нехватке подтверждений сохраняется только в истории, поскольку вызова провайдера не было. Ошибки API, отказы, незавершённые ответы и ошибки цитирования завершают запрос до записи в кэш и историю.

Каждый вопрос задаётся отдельно. В истории видны введённый вопрос, результат с источником или сообщение о нехватке подтверждений, время UTC, модель и ревизия. Повтор из кэша получает собственную запись. После изменения индекса у старых записей появляется пометка «устарела».

```powershell
.\build\Debug\rag_cli.exe --history .\build\demo.sqlite
.\build\Debug\rag_cli.exe --clear-history .\build\demo.sqlite
```

Первая команда показывает историю в порядке выполнения вопросов. Вторая удаляет все записи истории указанной библиотеки. Документы и кэш остаются доступны. Файл SQLite содержит вопросы и цитаты в открытом виде. Для хранения между запусками используйте `--db`. При запуске с одними файлами библиотека, кэш и история существуют в памяти до выхода из CLI.

### OpenAI Responses API

В этом примере используется отдельная база с демонстрационными документами. Новая библиотека и каждый новый документ получают политику `LocalOnly`. Команда `--documents` показывает имена и ID. Для отправки разрешите обработку библиотеки и каждого документа в ней. Если хотя бы один документ закрыт, весь вопрос завершается до поиска, кэша и чтения ключа. Политику можно вернуть командой `--policy` со значением `local-only`.

Удалённый вопрос удерживает блокировку записи SQLite с чтения политики до завершения операции. При одновременном запуске `--policy` по той же базе SQLite ждёт освобождения блокировки до трёх секунд. Если вопрос всё ещё выполняется, CLI сообщает «Библиотека занята». Если отзыв разрешения зафиксирован первым, вопрос завершается без HTTP-вызова.

**Демонстрация без сети**

```powershell
$cli = '.\build\Debug\rag_cli.exe'
$db = Join-Path .\build ("openai-demo-" + [guid]::NewGuid().ToString("N") + ".sqlite")
$question = 'Какой срок приёмки?'
& $cli --db $db .\data\demo\contract.txt $question
& $cli --db $db $question
& $cli --documents $db
& $cli --db $db --openai $question
ctest --test-dir build -C Debug -R 'openai|sqlite_migration_v8' --output-on-failure
```

Вторая команда с вопросом читает результат `MockProvider` из кэша. Команда с `--openai` получает отказ в обработке. Тесты используют подставной транспорт и проверяют отправленные поля, бюджет, ошибки провайдера и повтор после перезапуска. В тесте CLI с разрешёнными политиками переменная `OPENAI_API_KEY` удаляется из окружения тестового процесса.

**Отдельный запрос к настоящему OpenAI**

Используйте уже настроенный ключ. По умолчанию CLI читает пароль общей учётной записи `Rag-bot/OpenAI` из Диспетчера учётных данных Windows (раздел «Учётные данные Windows», пункт «Добавить общие учётные данные»). Для разработки можно добавить `--dev-env-key`, если `OPENAI_API_KEY` уже задана в окружении процесса.

```powershell
# Продолжение примера с новой базой, где ID contract.txt равен 1.
& $cli --policy $db library allow-remote
& $cli --policy $db document 1 allow-remote
& $cli --db $db --openai --model gpt-5.4-mini-2026-03-17 $question
& $cli --db $db --openai --model gpt-5.4-mini-2026-03-17 $question
& $cli --history $db
```

Первый разрешённый запрос может расходовать квоту API. Второй использует сохранённый результат при совпадении вопроса, ревизии и профиля. При ошибке API CLI завершает команду, повтор можно запустить вручную. `--model` задаёт ID модели с поддержкой Structured Outputs. Значение по умолчанию — `gpt-5.4-mini-2026-03-17`. При ротации ключа передавайте новую публичную метку, например `--credential-scope rotation-2`, и используйте её для всех вопросов этого профиля. Смена метки выделяет новый кэш без чтения ключа при попадании. У гибридной библиотеки укажите `--embedding-model <GGUF>` перед `--openai`.

WinHTTP отправляет HTTPS POST в OpenAI Responses API. Данные запроса включают вопрос и до восьми отобранных локальным поиском фрагментов с ID в пределах 16 КиБ сериализованного запроса. Резерв ответа — 1024 токена. `store: false` отключает хранение ответа как объекта Responses API. Условия обработки данных сервисом описаны отдельно. [OpenAI Data Controls](https://developers.openai.com/api/docs/guides/your-data)

Для JSON используется согласованный `nlohmann/json` 3.12.0 (MIT). CMake закрепляет SHA-256 архива `42f6e95cad6ec532fd372391373363b62a14af6d771056dbfc86160e6dfff7aa`. Для сборки из локальной копии передайте `-DRAG_NLOHMANN_HEADER=C:/Downloads/json.hpp`. CMake сверит заголовок по официальной SHA-256 `aaf127c04cb31c406e5b04a63f1ae89369fccde6d8fa7cdda1ed4f32dfc5de63`. [Официальный релиз](https://github.com/nlohmann/json/releases/tag/v3.12.0)

### Полнотекстовый и гибридный поиск

По умолчанию поиск использует SQLite FTS5 с токенизатором `unicode61` и ранжированием BM25. Вопрос разбивается тем же токенизатором, каждое слово экранируется, а выражение передаётся параметром SQL. Кавычки, скобки и операторы из вопроса обрабатываются как ввод пользователя. Для смыслового поиска укажите файл GGUF при индексации и при каждом запросе по этой библиотеке.

Для Windows x64 используйте MSVC 2022 и локальный архив исходников llama.cpp **b6500**. Гибридный профиль объединяет первые 20 совпадений BM25 и первые 20 по косинусной близости. Вклад места `r` равен `1/(60+r)`, отсчёт начинается с 1. При равенстве используются ID документа и номер фрагмента. Из результата выбирается до восьми фрагментов, сначала до двух на документ, затем оставшиеся по рейтингу. Qwen использует последний токен, L2-нормирование, 1024 компоненты и отдельную поисковую инструкцию для запроса.

При импорте токенизатор Qwen отмеряет до 400 токенов на фрагмент, включая служебные токены. Соседние фрагменты перекрываются в пределах одного блока максимум на 60 токенов. Без модели используются пределы 400 и 60 байт UTF-8 с разрезом по границе символа. Цитата из части длинной строки TXT сохраняет исходную строку и включительный диапазон символов с единицы. У PDF сохраняется страница, у DOCX — часть и абзац либо ячейка. Диапазон отсчитывается внутри извлечённого блока. Лимит входа адаптера для запроса с инструкцией и EOS остаётся 2048 токенов.

### Импорт DOCX и поиск по трём форматам

DOCX обрабатывается локально. Программа читает основной текст, ячейки таблиц и отдельно связанные части колонтитулов и сносок. Нумерация с единицы начинается заново в каждой части. Для абзаца выводится его номер, для текста в таблице — номер таблицы, строки и ячейки. Номера строк и ячеек соответствуют их порядку в таблице.

```powershell
$db = Join-Path .\build ("mixed-demo-" + [guid]::NewGuid().ToString("N") + ".sqlite")
.\build\Debug\rag_cli.exe --db $db .\data\demo\contract.txt .\data\demo\backup-protocol.pdf .\data\demo\backup-register.docx "Вега"
.\build\Debug\rag_cli.exe --db $db "Тритон"
.\build\Debug\rag_cli.exe --db $db "Какой срок приёмки?"
.\build\Debug\rag_cli.exe --db $db "Orion snapshot"
```

В новой базе «Вега» находится в абзаце 2, а «Тритон» — в таблице 1, строке 2, ячейке 2. У обеих цитат ID документа 3. TXT сохраняет строку 4 и ID 1, PDF — страницу 2 и ID 2.

Программа распаковывает только нужные XML-части и читает их из памяти. Лимиты DOCX — 64 МиБ для входного файла, 128 МиБ заявленного распакованного объёма, 8 МиБ на XML-часть и 32 МиБ на прочитанные XML в сумме. Вложенность XML ограничена 64 уровнями. Внешние связи пропускаются, вложения и макросы остаются данными архива. CLI предупреждает о частичном извлечении при встрече неподдерживаемых элементов, например текстовых блоков в фигурах. Ошибка любого нужного XML-файла отменяет импорт этого DOCX целиком, после чего CLI обрабатывает остальные файлы.

При первом открытии библиотеки схемы 1–8 программа сохраняет резервную копию через SQLite Backup API в соседней папке `<имя базы>.v<исходная версия>-backup`. Копия называется `library.sqlite`. Если папка занята, используется числовой суффикс. Библиотека сохраняет исходные блоки отдельно от поисковых фрагментов, включая координаты TXT, PDF и DOCX. Документы, их ID и ранее записанные цитаты сохраняются. Библиотеки схем 1–3 получают постоянный ID, политику `LocalOnly` и начальную ревизию 0. Для схем 4–7 миграция сохраняет ID библиотеки и повышает ревизию.

Схема 8 перестраивает полнотекстовый индекс с учётом границ слов и чисел. Край фрагмента и начало перекрытия выбираются по правилам `unicode61`. Например, запрос `15000` больше не получает полнотекстового совпадения на границе внутри `150000`. Если одно непрерывное слово или число само превышает бюджет целого фрагмента, его части сохраняют координаты и доступны векторному поиску. FTS5 пропускает эти части, поэтому такой сверхдлинный термин недоступен через полнотекстовый поиск. Обычные слова и числа рядом с ним индексируются целиком.

При миграции со схем 1–7 перестраивается полнотекстовый индекс. Для прежней гибридной библиотеки выполните `--reindex $db --embedding-model $model` с локальными весами. Команда заново делит исходные блоки, рассчитывает векторы и публикует новую ревизию одной транзакцией. Схема 9 сохраняет списки утверждений. При переходе с версии 8 поисковый индекс и ревизия сохраняются, старые цитаты переносятся в историю с координатами, а прежний кэш очищается.
