# RAG-чатбот по документам

Учебный проект по дисциплине «ООП. Современные паттерны» (Москва, 2026). Планируется настольное приложение для вопросов по библиотеке PDF, DOCX и TXT с подтверждающими цитатами и ссылками на источники.

Основной пользователь MVP — руководитель проектов организации N. Он сопоставляет ТЗ с договором и ищет сведения о принятых, выполненных и отложенных решениях. Организация N — условное обозначение; приложение может использоваться и для других документов.

**Текущий этап — 4, подготовка рабочего ядра.** Вертикальный прототип этапа 3 зафиксирован версией `v0.3`. Архитектура зафиксирована версией `v0.2`, продукт — `v0.1`. Заявка и объём приняты преподавателем 15.09.2026, уровень — продвинутый.

**Стек прототипа** — C++20 и CMake под Windows x64. В архитектуре следующих этапов предусмотрены Qt 6 Widgets, SQLite, гибридный поиск, OpenAI Responses API, локальная генерация через llama.cpp и хранение ключа в Windows Credential Manager.

Одна кодовая база должна поддерживать сборку с внешним API и ключом пользователя и сборку с локальной моделью. Конфиденциальные документы обрабатываются локально, повторные вопросы при неизменных индексе и модели — из кэша. OCR не входит в MVP.

THIN и FAT обе выполняют поиск локально и включают модель эмбеддингов; FAT дополнительно содержит локальный генератор. История сохраняется для просмотра, каждый вопрос самостоятельный — это уточнение студента от 26.10.2026.

**Гипотезы:** до 30 документов в рабочем наборе, около 20 вопросов в день, ответ не более чем за 5 минут после индексации. Число файлов не является искусственным пределом; время зависит от объёма текста, оборудования и модели. Предполагаемая цена — **15 000 ₽ за лицензию**, разовая покупка; внешний API оплачивается отдельно. Скорость, качество, экономия времени и готовность платить ещё не измерены.

[Предыдущий прототип](https://github.com/Tkhn-one/Rag-chatbot_docs) используется как источник идей; история этого проекта ведётся отдельно.

## Сборка и демонстрация

Нужны MSVC из Visual Studio Build Tools 2022, Windows SDK и CMake 3.21 или новее. Откройте Developer PowerShell или Developer Command Prompt для Visual Studio 2022. Перед сборкой перейдите в папку проекта, где находится `CMakeLists.txt`. Команда `cmake -S .` использует текущую папку как источник. В Developer Command Prompt для перехода можно использовать `cd /d "C:\Projects\Rag-bot"`, подставив свой путь.

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DBUILD_GUI=OFF -DWITH_LOCAL_LLM=OFF
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
.\build\Debug\rag_cli.exe .\data\demo\contract.txt "Какой срок приёмки?"
```

Готовую программу можно запустить из любой папки. В Developer Command Prompt подставьте свои полные пути и введите всю команду одной строкой. Первый путь запускает `rag_cli.exe`, второй передаёт ему TXT-файл, третий аргумент задаёт вопрос. Если ввести путь к TXT отдельно, Windows откроет его в текстовом редакторе. В PowerShell перед первым путём добавьте `&`.

```cmd
"C:\Projects\Rag-bot\build\Debug\rag_cli.exe" "C:\Projects\Rag-bot\data\demo\contract.txt" "Какой срок приёмки?"
```

На учебном договоре программа показывает цитату «Срок приёмки результата составляет десять рабочих дней.» из строки 4. Вопрос «Астрономия» показывает сообщение об отсутствии подтверждения. Для пустого файла или вопроса программа выводит объяснение и возвращает ненулевой код завершения.

Прототип принимает один TXT-файл размером до 8 МиБ в UTF-8 или UTF-16 с BOM. Он хранит текст в памяти и использует непустую строку как фрагмент. Поиск сравнивает целые русские и английские слова без учёта регистра. При равном числе совпадений выбирается первая строка. Тестовый провайдер возвращает найденный текст, а приложение сверяет цитату с источником. Этот сценарий работает без сети и API-ключа.

Поиск различает словоформы. Вопрос «Какой тип договора» не даёт совпадений, поскольку в заголовке учебного файла стоит слово «договор». Запрос «договор» найдёт заголовок. Тип договора в учебном файле отдельно не указан.

## Оформление по методичке

Заявка содержит пункты раздела 17, описание продукта — пункты приложения А. Для этапа 1 определены пользователь, проблема, способы решения, MVP, ценовая гипотеза и наблюдаемый критерий готовности. Измерения выполняются при появлении работающего продукта и не выдаются за уже полученные результаты.

`AI_LOG.md` хранится в `docs/` рядом с проектными записями и доступен по ссылке выше. Раздел 10 методички допускает другую логически объяснённую структуру. `PROJECT_BRIEF.md`, `APPLICATION.md` и `ROADMAP.md` дополняют документацию постановкой, заявкой и планом; `AGENTS.md` задаёт локальные правила работы.

Предметные типы находятся в `include/rag/domain/`, сценарии в `src/application/`, чтение и поиск в `src/infrastructure/`, вывод в `src/presentation/`. В `apps/` собираются компоненты прототипа. Тесты находятся в `tests/`, учебный договор — в `data/demo/`.
